# 法院传票开庭登记

选用本次配置的开庭表。写入前实时读取表和字段，发现目标或类型不符则停止写入。本文件所述日历专指飞书日历；Mac 日历与提醒按 [Mac 同步说明](mac-sync.md) 单独处理。

工作范围：上传法院传票、明确的开庭通知或开庭变更通知；识别、增量写入开庭表、撞期比对、日历同步和冲突通知。不要把送达日期、文书落款日期、答辩日期当作开庭日期。若传票未载明明确开庭日期、起始时间或地点，只写可确认信息并标 `待核`，不创建日历日程；不能从旧传票猜新日期。阅读 [字段映射与飞书配置](hearing-fields.md)。

## 识别与日期

- 逐页读取原件（含 PDF 文字层及图片 OCR），记录证据所在页，分别提取案号、法院、开庭日期与时刻、地点、开庭是否取消或变更、案由、程序类型及所有当事人、第三人。只从正文或抬头提取，不凭文件名推测。可选 `../scripts/normalize_date.py` 将中文日期转 `YYYY-MM-DD`；同时支持 `○`、`〇`、`零`、`Ｏ`、`O`，以及“二○二六年一月二十二日”等写法。不能确定年份或时区时留待核，不编造。
- `当事人` 一列只记原告、被告、上诉人、被上诉人、再审申请人、被申请人、申请执行人、被执行人等真实名称，**不按诉讼地位拆列**；去重并用 `；` 分隔。`第三人` 单独列出第三人名字，如无则留空。不能把“你”“你单位”当事人姓名写入。
- `程序类型` 仅在文书明确写“简易程序”或“普通程序”时录入简易/普通。没有提及则留空；再审/二审不是简易或普通的自动依据。若字段选项不匹配，说明问题，不擅改类型。
- `案件名称` 优先从“原告甲与被告乙……一案”或“甲诉乙……一案”提取，统一为“甲诉乙＋案由”。其次处理“你与乙……一案”“甲与你……一案”，仅在抬头及语境**唯一明确**“你”指谁时用真实姓名替换；不明确则留空待核。执行案件只在文书实际为可办理的开庭传票时处理“甲申请执行乙……一案”，格式为“甲申请执行乙＋案由”，不因例子而处理一般执行通知。去掉“申请执行人……与你单位……”等程式化引语、角色前缀和重复拼接的姓名。案件名称必须含双方真实当事人（或申请执行人、被执行人）以及能确认的案由；缺任一项时留空待核，不编造案由。

## 判重、撞期与写入

先按 [平台接入](agent-setup.md) 验证本会话的飞书工具；有已授权的官方 Lark CLI 时，读取其 lark-base 技能与本机命令说明。分页读取开庭表中本次查询范围内的所有有效记录。附件、表格写入与日历完成状态分别回读。

1. 以 `唯一标识`、案号、开庭起始时刻及原传票核对同一场开庭；重复上传更新已有记录，不新增；收到明确改期开庭通知时，找到同一案件原开庭记录并更新（旧时间写到 `备注`，注明变更来源），不得保留两个都显示有效的日程。变更含糊则不覆盖旧记录。
2. 将不同案件的**同一当地日历日**视作潜在撞期，即使时段不重叠也标 `冲突` 并写明“同日不同时间”；若已知时间区间重叠则写明“时段重叠”。同案重复/同场多名当事人不构成撞期。只对有效开庭比较；缺日期则待核。新纪录与已有纪录冲突时，更新冲突两侧记录，不能只标新行；旧冲突解除后重新计算并清理原标记。地理位置不同且间隔短仍保持同日提示。
3. 写 `节点时间` 为日期时间型（北京时间），地点按传票原文；`节点类型`、`文书类型`、`核验状态` 依表内实际选项。`来源文书` 是附件列，按已验证的上传与关联方式写原件；不能把文本 URL 冒充附件。`唯一标识` 保留以便判重，勿改其他案件的行。写入前尽量让有效记录具备下述最少字段；字段缺失时报告名称与类型，不擅自在原表新增字段。
4. 已授权飞书日历时，按本机命令说明查询可写日历及原事件。起始时间取开庭时间；原件未记载结束时间时，用开始后 2 小时作排程估值并注明。无用户要求时不添加参与者、邀请或提醒。创建或更新后核验所属日历、时区、起止时间和提醒设置，再将事件 ID 回写到本行。改期沿用原事件；取消或删除按 [定向变更](agent-setup.md#飞书定向变更) 核对后执行。表内日历视图与日历事件分别报告。
5. 冲突记录的红色填色和**冲突才发送的飞书消息**交由飞书多维表格配置（见字段映射），不能因正常开庭发送冲突警报。仅状态从“非冲突”进入“冲突”时通知一次；同一次重试不得重复通知。若用户未完成自动化，报告“表已标冲突，通知未配置”，不声称已提醒。飞书日历成功与飞书消息成功应分别回读/核验。

输出简短汇总：新建/更新行数、案件名称与各方、开庭时间地点、撞期案件及冲突类型、日历 event ID、通知是否实际发送、来源文书、待核事项。不要显示凭证，也不要因外部同步失败反复新增记录。
