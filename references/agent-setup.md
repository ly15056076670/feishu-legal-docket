# 平台接入与飞书定向变更

本次任务需要的资源由用户提供或从已授权集成读取。可在不随库发布的 `config.local.json` 保存 Base 标识、开庭与节点表 ID、保全表 ID、可选飞书日历 ID 和字段映射。可参考 [配置示意](../examples/config.example.json)。该文件由 Agent 作为任务配置读取。令牌、密钥及授权由宿主工具或官方 CLI 管理。

## 核对接入

1. 优先使用宿主提供的飞书集成。分别核对多维表格列表、字段和记录读取，附件上传与回读，以及本轮需要的写入、删除或日历权限。
2. 宿主未提供相应操作时，可以使用[飞书官方 Lark CLI](https://github.com/larksuite/cli)。按官方说明安装和授权，在执行环境运行 `lark-cli auth status` 检查登录状态。读取本机随 CLI 提供的 `lark-base`、`lark-calendar` 指引及命令帮助。Base 通常由表和字段列表、记录查询、按 ID 更新或删除等独立操作组成。附件按[飞书附件规范](https://open.feishu.cn/document/docs/bitable-v1/faq?lang=zh-CN)上传并关联。
3. 列出配置中的目标表和字段，以 ID 核对，不按同名表猜测。日志或结果中只写完成判断所需的业务标识，保存的来源以原件为准。缺哪个能力就说明影响到哪个交付环节，继续完成仍可验证的提取或计划。

## 飞书定向变更

- **新增或更新**。先按案号、节点类型和稳定键查询。有关开庭改期，稳定键应标识同一场开庭，沿用原记录 ID 和原日历事件 ID。若一份文书可能对应多条记录，先把歧义列出来。保留人工字段和原有公式。新增及更新之后回读，核对关联原件。
- **取消或删除**。收到有效取消文书或明确取消要求后，先定位原记录、稳定键和关联日历。可以按表内已有选项标记取消，保留来源；要求实际删除时，以用户指定且重新核对过的 Base、表及具体记录 ID 执行，再回读确认该行状态。需要处理关联日历时单独按原事件 ID 定向处理并回读。记录与日历操作有一侧未完成时，记录已完成的一侧和待办 ID，重试先回读。
- **自动更新**。上传重复文书或新的改期通知时，可由本工作流重新识别并更新。开庭撞期需重算本次变更影响的两侧，飞书红色填色、预警及消息的触发规则在目标 Base 里配置。后台定时任务或监听由部署环境另行配置。现有业务表、日历或通知目标的授权不会随 Skill 一起安装。
